## チャタリング対策（実施済み）

### 症状

E キーの連打ログを取ったところ、80ms 未満の間隔でダブル入力が頻発。

### ログ分析

- チャタリング判定（80ms 未満）: 9 件、最大 71.2ms / 最小 2.4ms
- 正常打鍵の最短間隔: 88.6ms（その下の集中帯は 102〜119ms）
- 安全域は約 71.2 < x < 88.6 ms

### 対応

`boards/shields/ZaruBall/ZaruBall.dtsi` の `kscan0` ノードに以下を追加:

```dts
debounce-press-ms = <5>;
debounce-release-ms = <30>;
```

意図:

- press はデフォルト維持（打鍵感優先）
- release を 30ms に上げて「押下中の一瞬の release バウンス」を吸収
- グローバル Kconfig (`CONFIG_ZMK_KSCAN_DEBOUNCE_*`) ではなく DT property を選択（局所スコープで安全）

### 次のステップ

1. ファーム焼き直して再ログ取得
2. 80ms 未満のイベントが消えたか確認
3. 残るなら release を 45ms に引き上げ（B案）
4. それでもダメなら press 8ms / release 50ms（C案）

### 一次情報

- ZMK debounce: https://zmk.dev/docs/features/debouncing
- charlieplex bindings: https://github.com/zmkfirmware/zmk/blob/main/app/module/dts/bindings/kscan/zmk%2Ckscan-gpio-charlieplex.yaml

## 紫 LED フリーズ問題（調査のみ、対応保留）

### 症状

トラックボール使用中、突然右側 LED が紫で固定 → キーもトラックボールも操作不能。電源リセットで復帰。頻度は高くない（保留決定）。

### 確定情報

- **caksoylar/zmk-rgbled-widget では MAGENTA (color=5) は `BATTERY_COLOR_MISSING` のデフォルト**で、用途は "battery not detected, or **peripheral disconnected**"
- 同時に `CONFIG_RGBLED_WIDGET_LAYER_3_COLOR=5` で **Layer 3 (Mouse) の表示色も MAGENTA**
- → 紫の意味が二重になっており、フリーズ時にどちらか観測不能
- PMW3610 ドライバの SPI MOSI/MISO 同一ピン設定（P1.13 重複）は **正常仕様**。inorichi/zmk-pmw3610-driver の公式サンプルでも `<NRF_PSEL(SPIM_MOSI, 0, 17)>, <NRF_PSEL(SPIM_MISO, 0, 17)>` と同一ピン記述。**bug ではない**

### 推定原因（確度順）

1. **右側 central のフリーズ**（高） — PMW3610 ドライバ or 入力処理パイプライン hang。LED は最後の状態で固定
2. **PMW3610 force-awake の副作用**（中） — 連続 SPI で nRF52840 を詰まらせる可能性
3. 左 peripheral 落ちのみ（低） — 「右側のキーも効かない」観察と矛盾

### 切り分け提案（未実施、再発頻度上がったら順に実施）

- **Step 1**: `CONFIG_RGBLED_WIDGET_LAYER_3_COLOR` を MAGENTA 以外（WHITE=7 推奨、CYAN=6 は Layer 4 と被る）に変更。**紫のままフリーズ → peripheral disconnected が真因 / 新色のままフリーズ → 右 central フリーズ**で切り分けられる
- **Step 2**: 右側に `CONFIG_ZMK_USB_LOGGING=y` を仕込んで USB シリアルログ取得
- **Step 3**: `ZaruBall.dtsi:215` の `force-awake;` をコメントアウトして頻度比較

### 失敗した調査

サブエージェントが SPI MOSI/MISO 同一ピンを「設定 bug」と最高確度で報告したが、**PMW3610 の慣行（双方向 1 線運用）を知らないと誤読する典型例**。一次情報（公式サンプル）で裏取りして却下した。

### 一次情報

- caksoylar/zmk-rgbled-widget README: https://github.com/caksoylar/zmk-rgbled-widget
- inorichi/zmk-pmw3610-driver: https://github.com/inorichi/zmk-pmw3610-driver

## Mac / Windows / Game の 3 OS 対応（実施済み）

ブランチ `feature/multi-os-support` で実装。

### きっかけ

Mac (デフォルト) で運用していたが、Windows でも同じ感覚で使えるようにしたい。ゲーム時は HRM/SandS が誤発動するので Windows 互換の専用レイヤーが必要。

### 既存ブランチの扱い

`feature/multi-device-support` (旧、`b5cac9f` 止まり) は **設計の方向性だけ参考**にして削除。理由:

- main から 20 commit 離れていてマージ不能
- iPad 対応など今は不要なものが含まれる
- 過去に `79b724e refactor: simplify keymap to Mac-only configuration` で意図的に取り除いた経緯がある

参考にした設計パターン:

- **OS ごとに MAIN/MOUSE を独立レイヤー化**（OS 検出はやらない、ZMK 流）
- LOWER/RAISE/SCROLL/CONTROL は OS 共通
- 言語切替マクロと mouse-layer hold-tap を OS 別に用意

過去 main の `59cc90a feat: gamemode` ～ `7e4df2c` 直前にあった game_layer も復元のひな形に流用。

### レイヤー構成（6 → 9 layers）

| # | 名前 | 用途 |
|--:|------|------|
| 0 | MAIN | Mac (デフォルト) |
| 1 | MAIN_WIN | Windows |
| 2 | GAME | Windows 互換ゲーム用、HRM/SandS 無効 |
| 3 | LOWER | 共通 |
| 4 | RAISE | 共通 |
| 5 | MOUSE | Mac |
| 6 | MOUSE_WIN | Windows |
| 7 | SCROLL | 共通 |
| 8 | CONTROL | BT/システム |

### 修飾キー入替方針（Mac → Windows）

基本は **`LGUI` ↔ `LCTL` 入れ替え**。ホスト側で同じショートカット（コピペ・タブ・保存等）が動く。

| 役割 | Mac | Windows |
|------|-----|---------|
| アプリ切替 row0 | `LG(GRAVE)` | `LA(TAB)` |
| 新タブ | `LC(T)` | `LC(T)` (共通) |
| HRM F | `LS(LEFT_GUI)` | `LS(LEFT_CONTROL)` |
| HRM G | `LEFT_CONTROL` | `LEFT_GUI` |
| HRM SEMI (Hyper) | `RS(RA(RC(RIGHT_GUI)))` | 共通（ホスト側 Hyper 設定で対応） |
| 親指 SandS 左 | `LGUI LANG2` | `LCTL INT5` |
| 親指 SandS 右 | `RA(RIGHT_GUI) LANG1` | `RA(RIGHT_CONTROL) INT4` |
| Mouse 層 ht_l2 | `LGUI` (lang2_mac) | `LCTL` (lang2_win = INT5) |
| Mouse 層 ht_l1 | `RA(RIGHT_GUI)` (lang1_mac) | `RA(RIGHT_CONTROL)` (lang1_win = INT4) |

### 言語切替

Windows で Mac の `LANG2/LANG1` 相当を出すために **`INT5` (無変換) / `INT4` (変換)** を採用。Microsoft IME のデフォルトで「無変換 = IME OFF」「変換 = IME ON」を割当てる構成にすれば、Mac とほぼ完全に揃う（モーダル切替）。

`LCTL+SPACE` は IME on/off トグルで状態が見えないので不採用。

### OS 切替キー配置

`CONTROL` レイヤーの BT 切替の並びに **`to_mac / to_win / to_game`** を配置。`to_mac` は BT0 + MAIN、`to_win` は BT1 + MAIN_WIN（プロファイル切替も兼ねる）、`to_game` は GAME 遷移のみ（ホストは Windows のまま）。

```
&trans  &to_mac  &to_win  &to_game  &bt BT_SEL 3  &bt BT_SEL 4  &bt BT_CLR  ...
```

過去 `bt_mac` macro は `to_mac` に統合・リネーム。

### GAME レイヤーの方針

`MAIN_WIN` ベースだが、**ゲーム中の誤発動を全部潰す**:

- HRM (LALT D / LS(LCTL) F / LGUI G) → 全て素直 `&kp D/F/G`
- 親指 `SandS LCTL INT5` → 素直 `&kp LEFT_CONTROL`
- 親指 `SandS RA(RCTL) INT4` → 素直 `&kp INT4`
- 親指 `lt RAISE SPACE` → 素直 `&kp SPACE`
- `HRM LSHIFT LEFT` → 素直 `&kp LEFT_SHIFT`
- 出口: 右上の `&to MAIN_WIN`

### LED 色マップ（9 layers）

`config/ZaruBall.conf` 更新。

| Layer | 色 | code | 補足 |
|------:|----|------|------|
| 0 MAIN | OFF | 0 | デフォルト消灯 |
| 1 MAIN_WIN | YELLOW | 3 | OS 違いを明示 |
| 2 GAME | WHITE | 7 | 特別状態 |
| 3 LOWER | RED | 1 | 旧 LAYER_1 と同じ |
| 4 RAISE | BLUE | 4 | 旧 LAYER_2 と同じ |
| 5 MOUSE | MAGENTA | 5 | 旧 LAYER_3 と同じ |
| 6 MOUSE_WIN | MAGENTA | 5 | MOUSE と統一（同時に存在しない） |
| 7 SCROLL | CYAN | 6 | 旧 LAYER_4 と同じ |
| 8 CONTROL | GREEN | 2 | 旧 LAYER_5 と同じ |

紫 LED 問題（peripheral disconnected と同色被り）の根本対策はまだ。再発したら `LAYER_5_COLOR` / `LAYER_6_COLOR` を WHITE 等に変える Step 1 が引き続き有効。

### 振り返り

- ブランチを切って main 起点で作り直したのは正解。`feature/multi-device-support` をマージしようとしたら scroll-stepper や trackball 軸変換の改善が全部巻き戻る危険があった
- LGUI ↔ LCTL の機械的入替で済むのは「Mac/Win でショートカットの修飾キー名だけ違う」というのが大半のため。Hyper (4-mod) は OS 側で設定する前提なので keymap では共通化できる
- gamemode は単独設計じゃなく **Windows レイヤーから派生**にしたことで、Windows のキー配置改善が GAME にも自動で反映できるはず（次の更新時に検証する）
